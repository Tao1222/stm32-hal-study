按键用上拉还是下拉输入，**完全取决于你的按键电路是怎么接的**。这二者是匹配关系，选错了，按键就无法正常工作[](https://cloud.tencent.com.cn/developer/article/2190875?policyId=1004)。

判断方法很简单，看你的按键在**不按下**时，把IO口拉到了什么电平：

### 1. 按键另一端接GND（地）→ 用“上拉输入”

- **电路**：按键一端连接IO口，另一端直接接GND。
    
- **原理**：
    
    - **不按下**：IO口和GND是断开的。启用内部上拉电阻后，IO口会被拉到**高电平**（默认状态为1）[](https://www.xcc.com/planet/post/4649)[](https://www.iczoom.com/t-solution/80130-industry.html)。
        
    - **按下**：电路导通，IO口直接连接到GND，电平被拉低为**低电平**（状态变为0）[](https://www.iczoom.com/t-solution/80130-industry.html)。
        
- **效果**：按键按下时，你读到的引脚电平会从 **`1`（高）变为 `0`（低）**，也就是“低电平有效”。这是最常见的设计[](https://cloud.tencent.com.cn/developer/article/2190875?policyId=1004)。
    

### 2. 按键另一端接VCC（电源）→ 用“下拉输入”

- **电路**：按键一端连接IO口，另一端直接接VCC（电源正极）。
    
- **原理**：
    
    - **不按下**：IO口和VCC是断开的。启用内部下拉电阻后，IO口会被拉到**低电平**（默认状态为0）[](https://www.xcc.com/planet/post/4649)。
        
    - **按下**：电路导通，IO口直接连接到VCC，电平被拉高为**高电平**（状态变为1）。
        
- **效果**：按键按下时，你读到的引脚电平会从 **`0`（低）变为 `1`（高）**，也就是“高电平有效”[](https://cloud.tencent.com.cn/developer/article/2190875?policyId=1004)。


另外，按键按下时一般有5-20ms的抖动，所以要消抖
### 阻塞式消抖（最简单，适合入门实验）

利用 `HAL_Delay` 延时避开抖动区。

c

if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) // 检测到按下（低电平）
{
    HAL_Delay(20);             // 延时 20ms，跳过抖动的不稳定区间
    if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) // 再次确认电平
    {
        // 执行按键任务（如点亮LED）
    }
    while (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET); // 等待按键松开（防连发）
}

- **优点**：逻辑直观，代码极短。
    
- **致命缺点**：**CPU 被完全占用**。延时的 20ms 内，单片机做不了任何其他事情。如果项目中还有数码管扫描或串口通信，会导致闪烁或丢包。
    
- **切记**：这种方法**绝对禁止**在中断服务函数中使用，否则必死机（结合你之前理解的 `HAL_Delay` 阻塞特性）。
### 方法二：非阻塞式消抖（最常用，适合项目实战）

利用定时器（如每隔 10ms 中断一次）或系统主循环，采用**“状态机/计数法”**，不阻塞 CPU。

**核心思路**：不在一瞬间做决定，而是隔一段时间（如 10ms）去读一次电平，**连续读到相同的电平 N 次**，才认为电平稳定了。

**伪代码逻辑**（在 10ms 定时器中断或主循环大 while 里调用）：

c

static uint8_t key_count = 0;      // 消抖计数器
static uint8_t last_state = 0;     // 上一次电平状态
void Key_Scan(void)  // 每 10ms 调用一次
{
    uint8_t current_state = HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0); // 读取当前电平
    
    if (current_state == last_state) // 电平没变
    {
        key_count = 0;               // 清零计数器
    }
    else // 电平发生变化（可能是抖动，也可能是真的按下了）
    {
        key_count++;                 // 计数器加1
        if (key_count >= 2)          // 连续2次（即连续20ms）都读到相同的新电平
        {
            key_count = 0;
            last_state = current_state; // 更新稳定的状态
            
            if (current_state == GPIO_PIN_RESET) // 确认是低电平（按下）
            {
                // 执行按键任务（触发一次）
            }
        }
    }
}

- **优点**：延时期间 CPU 可以自由地去刷屏、跑通信，资源利用率极高。
    
- **扩展性**：把 `key_count >= 2` 改成 `>= 3`，就是消抖 30ms，可以灵活适应不同按键的物理特性。
